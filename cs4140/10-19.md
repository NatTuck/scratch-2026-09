
# Supply Chain Issues

When you type `npm install {package}`, that downloads and installs software
on your computer that will at some point get run.

When it runs, it will run in your computer.

Idea:

- Might want to trust the source.
- Untrusted software might be malicous.
- It could delete your password and steal your operating system. Also,
bank details and use all your power for bitcoin mining.

Idea:

- We can just trust software in the default package repository.
- Can we? Why?
- That's probably a bad idea.
- The amount of vetting for software package authors is minimal.
- Any author of any dependency can run arbitrary code on your computer
if they update the package and then you pull the update.

## Universal Backdoor

Any software with these properties allows the software
developer to run arbitrary code against targeted users:

- Automatic updates
- User accounts

# How to avoid shipping malicious deps

Problem: A package on npm is updated, now it's malicious.

Two conditions need to be true for us to ship it:

- The package needs to be on our dependency list
- We need to update our dependency list (or have to have added the
package at the wrong time)

Conclusion:

- Less deps means less threat surface.
- Want to be careful about updating.

Problem:

- Updates fix security bugs.
- (Remember to run your package audit command, e.g. `pnpm audit`)

Crypto currency is great. It's automatic bug bounties.
