## Software Engineering -> Building Larger Software Projects

The hard part about larger software projects is managing state.

We've got a couple different kinds of state:

React does component state, or data that's specific to a component in
a web page (useState).

We have browser state independent of components in the store.

On the server we have state:

- One global variable.
- List of players.
- Map of game id => game state.

In memory is bad because if we reset we lose are data. We could persist
to disk for recovery.

Performance: Every operation for every user is bottlenecked on this one
data structure, making it a file would just make that worse.

We could use a database, which would be much better for both performance
and reliability.

If we want to have transient state (e.g. info about one game), we've got
to put it somewhere.

## What behavior do we want game state to have?

What info is in the state of a game?

- Players
- Board positions (both players)
- Hands for both players
- Decks for both player
- Discard pile

Who should have it?

- Players, board position, discard pile size, deck size: All players
- Hands: Only the owning player
- Decks: No player
