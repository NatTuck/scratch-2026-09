
## HTTPS and TLS

Web sites are "secured" by using "https" instead of "http" as the protocol.

This does two things:

- Encryption: Data (http request, http response) is encrypted in transit.
- Authentication: The response is signed by a digital certificate, confirming who
sent it.

Encryption is strong, mostly unbreakable in practice.

- Public key: RSA 2048, RSA 4096, ECC-DSA 384
- Digital signatures: (same as the public key algos)
- Symmetric key: AES, ChaCha20
- Cryptographic hashes: SHA256

Authentication is super sketchy.

- Need to be sure that you're really talking to the right server.
- Certificate authorities are companies that provide digital certificates,
asserting that some public key belongs to some company.

How do we know what certificate authorities to trust?

- We just trust our browser. They decide.
- Large set of certificate authorities with their public keys bundled in
common web browsers: Chrome, Firefox, Brave, Edge, Opera, Whatever Nonsense
Apple Ships
- Certificate authorities are sometime really dumb (private key 4 story)
- Certificate authorities are very consistently subject to national political
pressure.

Technical details:

- TLS is layered over TCP (or UDP/Quic), to do this encryption/auth/cert stuff.

## User Authentication

How do we tell which user (which human) is using our app?

- We have users make accounts.
- We say that each user has their own account.
  - Not necessarily true. Multiple humans could share a single account,
  or one human could have multiple accounts.
- Someone shows up to your app and says they're Bob Anderson.
How can we tell?
  - We have Bob set a password. He picks his birthday.
  - We have Bob enter his phone number so we can send an SMS verification
  code to it every single time he logs in because everyone knows his birthday.

## Passwords

- So bob picked "0493" as his password. If we can't remember his birthday,
how many guesses do we need to make to just guess our way in?
  - 10 ^ 4 = 10 thousand
  - 3600 seonds per hour, so like 3 hours.
  - If we just set up our app to lock people out after 20 guesses then
  this is secure.
- So we can do 4 number passwords.

Don't want to store plain-text passwords because:

- Someone might steal the password list.
