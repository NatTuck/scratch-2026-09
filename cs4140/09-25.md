
# User Stories and Workflows

## User Story

A user story is a small thing the user wants, written do so that:

- A developer can build it in roughly one sprint (we'll say that's a week for
  us).
  - This may mean we want to combine a series of small stories to give a one
    sprint task.
- The result is something the customer can actually see, use, and confirm.

The standard shape:

```
  As a [kind of user],
  I want to [do an action],
  So that [I get a benefit].

  When I [do the action],
  this happens: [the outcome].
```

Too specific:

```
  As a player,
  I want to till the ground,
  So that it's prepared so I can plant seeds.

  When I till the ground.
  this happens: The ground is in tilled state, planting a seed works
```

Too generic (this becomes clear when you try to enumerate the full
consequence list of each step):

```
  As a player,
  I want to plant, grow, and gather crops (like wheat, corn, etc),
  So that I can have the stuff I can get the crop loot to use or sell.

  When I prepare the ground and plant seeds and water them and wait for
  growth and harvest (all in sequence)
  This happens: I get the crop output items
  Edge case: 
  - The user tills sand (or some other invalid tile, including already tilled
  soil) rather than soil: No change, possibly error feedback
  - There was already a seed there: user's mouse falls on the ground.
  - Character doesn't have a hoe: Action isn't available
  - Character is too drunk: Hoe gets planted, can harvest for borken hoe.
```

Acceptance criteria are important:

- They let us know if we did the thing.

Can structure as: Given A, When B, Then C, Then D

Acceptance criteria should cover:

- Happy path
- Edge cases and failure cases
- What the user sees afterwards

Common pitfalls:

- Cramming several outcomes into one Then: Should make each testable result
clear.
- Stuff that can't be manually tested: useless

## Cast of Characters

We can make user stories clearer by defining characters.

- Alice the Admin, does admin stuff.
- Bob the Bungler, a player, always messes stuff up.

```
  As Bob,
  I want to be able to recover planted seeds without losing them.
  So that I can plant them in the right place.

  Given a seed (type X) planted in a tile.
  When we activate the tile with an empty hand.
  Then the tile has no planted seed.
  Then the tile is tilled ground.
  Then character's hand has a seed (type X) in it.

  Note: test with X = tomato, wheat
```

## Manual Testing

To do manual testing, the human tester starts at the initial state, does the
proposed actions, and sees what happens.

If the results match the story, test succeeded.

## Automated Testing

Stories can typically also be straightforwardly translated into
automated tests, both unit tests and integration tests.

- Unit test: Test one function
- Integration test: Test a sequence of functions / actions
- End to End test: Test a *complete* sequence
  - Start from the program not even running.
  - Simulate the whole sequence of actions up to some goal state (every click,
    input, etc).

A user story typically gives us either a unit test or an integration test.

## Several stories in sequence is a Workflow

- A workflow is closer to what an integration test would check.

Examples ( a workflow, component stories):

- Create new character and complete the tutorial.
  - Fill in and submit the new character form.
  - Tutorial Step 1
  - Tutorial Step 2
  - Tutorial Step N
  - Upon tutorial completion, you get placed at your farm and the
    tutorial restrictions no longer apply.
- Log in and get to your farm.
- From your farm, harvest grown crops and replant as needed.
- Harvesting a crop, going to town, selling the harvest.
- Buying more land and planting crops on it.
- Eating a cow.
  - Buying a cow or get cow from farm to town.
  - Bring cow to butcher and get it butchered (costs money).
  - Bring meat home.
  - Cook in kitchen.
  - Eat.

## How much work does a story take?

Hours vs points

A point is kind of like an hour (or maybe (2^n)/2 hours), but nobody can blame you
if it's not an hour.

```
  As a player,
  I want to till the ground,
  So that it's prepared so I can plant seeds.
```

This is probably one point, because it's pretty straightforward once the
preconditions to start are met.

```
  As a player,
  I want to plant, grow, and gather crops (like wheat, corn, etc),
  So that I can have the stuff I can get the crop loot to use or sell.
```

10 points, who even knows what the intermediate steps are. Really, too
big, break it into pieces. Stories should probably be 0.5-5 points, more
than that is too big.

## "Epics"

An Epic is a story that's too big to finish in one sprint.

- We identify it.
- We split it into smaller stories (grouped together in the Epic to not lose
info we have).
- Then we assign some prefix of it.
